这是对当前代码和证据的工程判断，不是任意输入下零缺陷或全局最小实现的形式证明。

当前结构可以由以下关系解释：

```text
P = (L, R, K)                       日志、原始运行记录、可选工作区检查点
S = fold(L)                        身份、任务和判断状态
C = view_B(S, input, evidence(P))   有预算且可追溯的模型视图
A = model(C)                       待校验的类型化动作
(O, W') = execute(A, W, grants, control)
L' = L ++ events(A, O)
```

这些关系解释职责，不声称模型一定能完成目标，也不把外部世界和本地日志假装成一个跨系统事务。
进程中断后，未确认的世界状态会明确报告为未知，不会因重放日志而再次执行效果。

## 本轮实际发现和处理

| 问题 | 最终处理 | 证据 |
|---|---|---|
| 默认相对状态目录与绝对项目路径比较失效，私有状态可能进入项目快照/检查点 | 创建后立即规范化节点、状态和项目路径；拒绝私有目录包含整个项目的布局 | native_worker：相对目录检查点只包含公开文件 |
| IPC Start 同时传 Assignment 和已准备消息，长任务重复占帧 | Start 只传 limits/messages；Assignment 保留在冻结清单 | native_worker：200 KiB 任务正常启动 |
| 超长文件目标的错误元数据使内容裁剪无法继续缩短 | 先校验目标；空内容仍超预算时明确报错，裁剪检查 Control | artifact：超大目标立即失败 |
| 日志超大事件使分页游标不前进；渲染丢弃分页字段；任务日志也可无界返回 | 所有日志目标共用有界分页；超大项返回原始事件定位符；按 UTF-8 字节读取 event；渲染游标和定位符 | convergence：越过超大事件继续发现后续事实，读取完整事件片段 |
| 同一助手消息在传输、宿主、子进程和重放时校验不同 | 一个共享 assistant 契约；非法自定义模型结果记录为 model_error，不进入重放消息 | native_worker：非法结果留证据且续接成功；传输重复调用仍被拒绝 |
| 空 tool_calls 被当作未完成调用组，重放可能丢掉已完成消息 | 仅非空调用组进入 pending；缺少 start 或组间非法穿插明确失败 | native_worker：空调用列表保留消息；损坏前驱不静默重启 |
| 异步初始化/请求入队的取消检查与等待响应不一致 | 模型/MCP 共用受 Control 约束的异步等待；MCP 初始化和发现也继承取消 | mcp：取消挂起初始化并回收子进程 |
| 初始化剩余预算被存成以后所有调用的超时 | 存储配置时长；每次调用独立取得当前父预算与配置的较小值 | mcp：短初始化预算不缩短后来调用 |
| 后续动作取消时，先前拒绝说明可能没写入日志；排队节点仍会进入执行入口 | 先落盘拒绝说明；每批执行前检查 Control；已完成批次立即记录，其余保留给恢复 | convergence：拒绝事实保存、未运行的保留任务被恢复为 waiting |
| 串行/并行端口的 panic 处理不一致 | 两条路径均把节点 panic 变成运行报告；NativeWorker 仍为单工作区串行 | loop 与完整回归 |
| 子进程状态查询或一侧 reader 错误可跳过另一侧 reader 的回收 | 所有退出路径先停止进程，join 两个 reader，再返回状态/读取错误 | native_worker：取消、超时、检查点、FD 与进程回收回归 |
| 重复关系/关闭数据类型、三处状态标签、串行后多余的检查点锁和活动集合 | 共用 Edge/CloseOutcome/TaskStatus；活动执行为一个 Option；删除多余锁和关系动作别名；身份历史改为一次有序筛选 | 编译、Clippy、状态和图回归 |
| EJA 上下文环境变量无效时静默回退 | 构造器默认值确定；显式 builder/env 校验并返回错误 | native_worker：CLI 零预算明确失败 |
| show turn 可能经字符串模式转换进入执行分支 | show 目标闭集校验 | native_worker：show turn 在创建日志前拒绝 |
| CLI 交付测试读错冻结路径，靠请求里的相同关键词误通过；部分夹具含重复 tool id/旧目录布局 | 用真实 MCP 测试服务写入文件，再从检查点读取，核对 Observed.error 和精确内容；修正夹具 | native_worker：真实 CLI→MCP→工作区→冻结读取→验收 |
| 旧生成架构图未标明时效 | 在 .archify 下标明其历史属性；当前规范保持单一入口 | .archify/README.md |

## 保留内容及理由

- 旧 `ProposalConfirmed` 事件的读取：旧日志已经存在，不重写历史；新确认只写一条身份事件。
- 旧 Task/Assignment 缺失可选字段的反序列化默认值：使既有日志仍能读取；不再从文字猜测组或续接关系。
- 旧记录已包含继承消息、缺少 view_version 或工具结果 id 的读取兼容：它们是历史证据的解码规则；新记录只存父地址与本轮事实。
- 多条有效 Goal 中选择最新一条的投影：这是当前明确语义，不是隐含的唯一目标约束；显式替换会关闭目标 id。
- 通用 Worker 的 capacity、内存端口默认方法及 Noop 适配器：服务于宿主组合和测试；NativeWorker 没有并行槽位或备用执行器。

上述历史解码规则没有产生第二条新数据写入路径。直接删除会丢失既有记录的可读性，不能把这种删除当作结构简洁。

## 后续工程最小化（基线 2cbc39e 之后）

本轮按“一个职责一个机制”继续做减法，保留事实、投影、动作校验、受控执行、事实回写的闭环。

| 移除的重复 | 当前唯一机制 |
|---|---|
| 普通入口与 controlled 入口、默认转发、Noop 读取对象 | 每个端口只有一个必传 Control 的操作；缺失能力由 Ports 的 Option 表达 |
| 通用 capacity、串行/并行两套调度路径 | 一个执行所有者，按动作顺序运行，每项报告先落盘再运行下一项 |
| 子进程的镜像步数计数与多余启动限额 | 宿主校验步数/时间/响应，子进程只接收消息视图所需的 context_bytes |
| Store 实例的回合锁与日志租约双重互斥 | 日志租约独立排斥克隆及独立 Store；写游标仍由 append 锁保护 |
| ToolOutput 单字段包装、ArtifactContent 内嵌错误通道 | 工具直接返回 JSON Value；读取失败统一沿 Result → Observation.error 进入事实日志 |
| 文件和冻结产物的两套全文裁剪 | 共用有界文本读取、UTF-8 裁剪与编码后大小检查 |
| 匹配的 pending 集合、剩余行计数、完成集合和二次排序 | 按命中位置直接维护有序结果，窗口结束位置由位置与 after 推导 |
| 提案确认的“是否待确认→再找事件→再解码” | 一次取得待确认提案投影，再验证权限与目标 |
| OpenTaskInput 中间结构、重复读取任务表、拒绝通知副本 | 使用 TaskOpen 事实类型；复用同一投影；从已收集拒绝流判断是否首次通知 |
| CLI 各分支的打印错误/失败退出模板 | 类型化命令和一个 Result 错误出口；配置解析共用同一规则 |
