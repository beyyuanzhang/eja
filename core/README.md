# EJA Core

一个数据库对应一个持续的 EJA。它接收有来源的经历，从中保留或修正关切，在一次有界回合中借助模型作判断，并接收行动的实际结果。工作、谈话和独处使用同一条循环。

```text
notice → view → judge → keep / release / recall / act / rest
           ↑                  │           │
           └── 新判断或宿主回执 ─┘           结束本轮
```

## 接入一个应用

这是独立的 Rust crate。应用用路径依赖引入 `eja-core`，为一个主体调用 `Eja::open(path)`。宿主选择何时唤醒，使用 `notice` 写入人的原话、环境观察或时钟信号，然后调用 `turn(grants, steps, judge, perform)`。示例在 `examples/loop.rs`，只使用公开 API。

- **模型适配器**实现 `judge(&View) -> Result<Judgment>`。适配器将视图与可用工具说明发给模型并解析结构化回答。每个判断引用一个已经存在的事实 ID。例如 `{"basis":1,"choice":{"op":"keep","concern":null,"text":"下次谈起时，先听完"}}`。旧关切用原始 ID 修正或释放。每项关切的 `basis` 指向最新一次修正所依据的事实。模型若觉得这项关切与处境有关，可返回 `{"basis":1,"choice":{"op":"recall"}}`，下一步视图即可看到该事实的原文和来源。这个选择占一步；原文已在最近一页时只呈现一次。装好语义模型后，core 会在每次判断前自动从整个旧历史补充候选。按页查询历史仍可调用 `history`、`concerns`。
- **能力适配器**实现 `perform(Call) -> Outcome`。能力名和参数由应用定义；文件、消息和其他外部操作都从这个接口接入。core 核对这一轮获准的名称，先提交判断，再交出调用。适配器负责校验参数、资源范围和实际操作权限，报告观察、失败或未知。关切仅代表 EJA 自己的理解；用户授权、向外发言和对外承诺由宿主明确控制。
- **回合**在记下、修正、放下或取得回执后重新询问模型；选择静默或用完步数即返回。模型和能力调用各自的超时、取消及输出限制由适配器执行。模型调用出错会向调用方返回错误。需接异步运行器时也可按 `view → decide → finish` 分步使用。
- **历史**用追加的事实保存。关切保留原始 ID 和最后一次修改的 ID。视图固定在一个 revision，显示最近 8 条事实和 8 项关切；收到 `recall` 时可额外带回 1 条指定的旧事实，每条原始事实的 JSON 上限为 8192 字节，可通过游标继续读取。大产物由能力保留，回执可以写入产物地址。这两个上限以及 SQLite 都是原型实现选择。
- **中断和竞争**。同一版本的视图只允许提交一个判断。并发失败后重新取视图作判断。重启只读取历史；已经记录的行动如果缺少回执，其效果仍然未知。宿主可以按行动 ID 查询外部结果，再调用 `finish`，同一份回执可安全重交。需要外部幂等的应用应将主体标识与行动 ID 一起传给能力。重开数据库不会自动重试真实操作。

## 从全历史召回

在 `core/` 下运行 `./scripts/install-memory-model.sh` 安装固定版本、校验 SHA-256 的多语言 E5 权重。运行期在本机使用 ONNX Runtime。部署时可用 `EJA_MEMORY_MODEL` 指向模型文件与配置 encoder.json 所在的目录。新 checkout 未安装权重时，普通日志仍可使用，`View.related` 为 `null`；显式调用 `search` 会返回模型未安装的错误。

Core 将 Unicode 原文交给 `Encoder`，分别请求 passage 或 query 向量。用 `Eja::open_with_encoder(path, encoder)` 可以直接注入实现；关闭默认 Cargo feature 即可独立于 ONNX 构建。向量维数由编码器声明，查询前缀、分词、池化和语言覆盖由适配器决定。内置 ONNX 适配器优先使用已安装的 multilingual-e5-small（384 维），也能读取旧的 BGE 中文安装和索引。切换编码器时，原始事实和 ID 共享；每个向量空间在同一数据库内单独建索引并按需补齐，切回时可复用。

每次 `view()` 用最近一次观察作为查询。神经编码器给查询和旧经历映射到同一向量空间，SQLite 按余弦距离在此版本的**整个旧历史**中排序。最近一页已经呈现过的事实会排除，最多 4 个候选进入 `related`。候选携带原始事实、来源和相似度。模型可以用候选 ID 作为判断依据，也可以忽略它。应用还可以用 `Eja::search("换一种说法的线索")` 显式查询截至当前版本的全部记录。点名读原文的 `recall` 仍独立可用。

- 人的原话、时钟和环境观察、记下的关切、能力调用的名称与参数、行动回执都参与建索引。仅含控制信号的判断仍可按 ID 阅读。
- 长文本切成最多 384 个字符的片段，匹配后返回整条原始事实。相同片段只编码一次，保留每次出现的事实 ID，匹配时取当前版本内最近的一次。若命中已被修改的关切判断，还会附上该关切的最新修正或释放记录。自由文本中的两句矛盾陈述需要模型结合来源判断。
- 首次查询会补建所需历史，此后按事实 ID 增量推进。每批的向量、事实引用和进度在一个事务内提交，可在中断后继续。模型与分词器的指纹绑定索引，避免混用向量空间。
- 当前使用精确近邻查询，耗时随不同片段的数量增长。取回的是相似候选，分数只用于排序。跨语言匹配质量取决于编码器学到的语言表示。

设计依据见 [Dense Passage Retrieval](https://aclanthology.org/2020.emnlp-main.550/)、[多语言 E5 模型说明](https://huggingface.co/intfloat/multilingual-e5-small) 和 [SQLite 向量近邻查询](https://alexgarcia.xyz/sqlite-vec/features/knn.html)。

## 验证

在本目录运行：

```sh
cargo test --locked --all-targets
cargo run --locked --example loop
```

示例使用脚本化判断以便重复验证。它记住人的请求，关闭并重开数据库，在时钟唤醒时调用真实的本地文件计数能力。人要求“以后等我问起再看”后，下一次唤醒即静默。测试另行覆盖关切更正的来源、历史分页、过期判断、并发竞争、权限、回执与步数耗尽。

使用真实权重验证语义召回（在 `core/` 目录执行）：

```sh
./scripts/install-memory-model.sh
cargo test --locked --test semantic -- --ignored
cargo run --release --locked --example semantic_recall -- 1000000 1000000
```

最后一条命令生成临时 SQLite 日志，两个参数分别控制事件数和背景文本的多样性。它把六条目标原话散放在历史里，加入同领域干扰项，然后从普通视图用中文改写提问。输出首次补建时间、目标排名、重开后的视图延迟及实际向量数。批量输入用于验证已有大库的检索，不衡量逐条同步写日志的速度。
